# Разрушаемые арены и автореген

## Принцип работы

Режим включается отдельно для каждого кита через `/duels options <kit>`. Обычная
дуэль и турнирный матч используют один `DestructibleArenaService`.

Плагин не копирует кубоид и не сканирует арену. При первом изменении конкретного
блока в памяти сохраняется только его исходное состояние: координаты, материал,
BlockData и состояние tile entity при необходимости. Повторные изменения той же
координаты не создают новые копии.

По завершении боя восстановление проходит пакетами в главном потоке:

```yaml
destructible-arena:
  restore:
    blocks-per-tick: 100
    max-time-per-tick-ms: 2.0
    disable-physics: true
```

На каждом тике обработка прекращается при достижении любого лимита. Поэтому
размер bounds 100x100x100 сам по себе не создаёт нагрузку: память и время зависят
от числа реально изменённых блоков, а не от миллиона блоков кубоида.

## Настройка

```text
/duels setbounds crystal_arena min
/duels setbounds crystal_arena max
/duels options crystal
```

Включите `Разрушаемая арена`, затем нужные механики: ручную установку и ломание,
взрывы, кристаллы, якоря, TNT-вагонетки, TNT, кровати, жидкости, поршни и огонь.
Тип кита не определяется по имени.

Если режим включён, но одна из границ отсутствует, матч не запускается. Одна
арена не принимает второй матч во время активной сессии или восстановления.

## Разрушение и предметы

- все исходные блоки внутри bounds могут разрушаться разрешённым способом;
- блоки за пределами bounds удаляются из списка разрушения взрыва;
- исходные блоки арены при ручном разрушении не выпадают;
- расходники, поставленные игроком во время матча, могут выпадать при ручном
  разрушении и остаются частью отслеживаемой сессии;
- временные вагонетки, TNT, кристаллы и связанные Item-сущности маркируются
  идентификатором сессии и очищаются без поиска всех сущностей мира;
- жидкости, поршни, огонь и изменения сущностями проверяются событиями на
  пересечение границы.

Взрывы обрабатываются по `event.blockList()`: полного обхода региона нет, урон и
knockback игроков сохраняются, а блоки снаружи не повреждаются.

## Состояния и диагностика

Сессия проходит состояния `PREPARING`, `ACTIVE`, `FINISHING`, `RESTORING`,
`READY`; ошибки и отмены имеют отдельные состояния.

```text
/duels kitdebug crystal
/duels arena debug crystal_arena
/duels arena restorestatus crystal_arena
/duels arena restore crystal_arena
```

## Перезапуск и аварийное восстановление

Активные сессии периодически сохраняются в `plugins/Duels/arena-recovery.yml`.
Стандартный интервал 1200 тиков, то есть 60 секунд. При штатном выключении
снимок сохраняется ещё раз. Перед фоновой записью данные копируются, а Bukkit API
не вызывается асинхронно.

После запуска плагин читает незавершённые сессии, восстанавливает записанные
блоки тем же пакетным механизмом и удаляет только отмеченные временные сущности.
Изменение, случившееся после последнего аварийного снимка при жёстком падении
процесса, может не попасть в recovery-файл; штатный restart сохраняет актуальный
снимок.
